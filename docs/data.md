These large files are excluded from Git. The published, open
[Zenodo record 24502905](https://doi.org/10.5281/zenodo.24502905) supplies
all six source files required by the active analyses. The Mediterranean
FLUXCOM file is derived locally from the European FLUXCOM and Mediterranean
GLEAM files using script 02.

## Download and prepare the active inputs

From the repository root in a Linux/WSL shell, choose an **empty** input
directory, then download the six files and check their published MD5 hashes:

```bash
export EXEVES_DATA_DIR="/path/to/empty/input-data"
mkdir -p "$EXEVES_DATA_DIR"
for file in \
  ET_2001_2020_025_daily_eur.nc \
  gleam_e_mm_med_198001_202412_025_daily.nc \
  mswep-v2-8_tp_mm_med_197901_202012_025_daily.nc \
  gleam_e_mm_eur_2001_2020_025_daily.nc \
  mswep-v2-8_tp_mm_eur_2001_2020_025_daily.nc \
  masks.rda; do
  curl --fail --location \
    "https://zenodo.org/api/records/24502905/files/$file/content" \
    --output "$EXEVES_DATA_DIR/$file" || break
done
(
  cd "$EXEVES_DATA_DIR" || exit 1
  md5sum -c <<'EOF'
7b8a91112bdafb3d40b381fb31d9d67b  ET_2001_2020_025_daily_eur.nc
e762923846785f5d4d2e01748be81306  gleam_e_mm_med_198001_202412_025_daily.nc
48dc6ddfe4d14dcd5823d22562c8f24d  mswep-v2-8_tp_mm_med_197901_202012_025_daily.nc
913729c69bc39246289d2b16c36b6b0c  gleam_e_mm_eur_2001_2020_025_daily.nc
019c64bfef7c6b494881e455d65f372e  mswep-v2-8_tp_mm_eur_2001_2020_025_daily.nc
4dca8058b91f6e8f8850b52ac42d8c02  masks.rda
EOF
)
```

Only continue if every checksum passes. After installing the environment in
the [main README](../README.md), run the crop with the input directory as
the output directory so later scripts can find it:

```bash
EXEVES_OUTPUT_DIR="$EXEVES_DATA_DIR" python code/02_crop_and_merge_ET.py
```

The crop writes `ET_2001_2020_025_daily_med.nc`. It can overwrite an
existing file of that name. Then set `EXEVES_OUTPUT_DIR` to a separate
results directory before running analyses.

## Evidence from local file metadata

- The global GLEAM file's processing history names GLEAM **v4.2a** annual
  files, merging, gridbox averaging and nearest-neighbor remapping. The exact
  source files, target grid definitions and complete preparation recipe have
  not been recovered.
- The global FLUXCOM file identifies **FLUXCOM-X X-BASE 1.0**, CC BY 4.0,
  and a CDO merge of annual daily ET files from 2001 through 2020. Its
  metadata links to [FLUXCOM-X data documentation](https://gitlab.gwdg.de/fluxcom/fluxcomxdata).
  `code/01_download_xbase_from_icos.py` contains ICOS Carbon Portal links and
  may require authentication; run it with `--help` for options.
- The global MSWEP filename indicates version 2.8; its history records a
  land-mask multiplication. The provenance and access terms of the exact
  original and its land mask have not been verified.
- The Mediterranean GLEAM and MSWEP files record cropping histories.
  The new Mediterranean FLUXCOM file is cropped from the deposited European
  file. Its values and land fraction match the local historical Mediterranean
  file for 2001–2020; coordinate differences are at most 7.2e-15 degrees.
- `masks.rda` contains a `masks` table with latitude, longitude, land cover,
  region and other columns. Its original source and generation method remain
  unknown. The reference repository obtains a similarly structured mask from
  `pRecipe::pRecipe_masks()`, but equivalence to this file has not been
  verified.

The processed inputs are available for the analyses. Reproducing their
upstream processing from original products is a separate, unresolved
provenance task, including original source citations, grid definitions and
the mask-generation method.

[input-sha256.txt](input-sha256.txt) records SHA-256 checksums of nine
historical local files, including the old 2001–2021 Mediterranean subset.
These identify those copies, not their sources or licenses, and do not cover
the new subsets or separate annual inputs. From a directory containing those
historical files, verify them with
`sha256sum -c /path/to/repository/docs/input-sha256.txt`; hashing the large
global files requires reading tens of gigabytes.

## Working directories

`EXEVES_DATA_DIR` supplies script inputs; `EXEVES_OUTPUT_DIR` receives
generated NetCDFs and figures. The downloader has its own `--outdir` option.
Both path variables default to the current working directory. Scripts may
overwrite existing output files. The checked-in `figures/` directory contains
the clean 2001–2020 run and is not automatically updated. Script 08b instead
refuses to overwrite the European subsets.
